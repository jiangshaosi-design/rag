### 步骤 0：配置 Git 身份（必做）

```bash
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱@example.com"
```

> 邮箱会写进每一个 commit 并**公开可见**。若不想暴露真实邮箱，在 GitHub 的
> `Settings → Emails` 中开启 *Keep my email addresses private*，使用 GitHub 提供的
> `xxxxx+用户名@users.noreply.github.com` 作为 `user.email`。

### 步骤 1：创建仓库 —— ✅ 已完成

仓库已存在：**`jiangshaosi-design/rag`**（当前为 Private）

远程地址：

```
https://github.com/jiangshaosi-design/rag.git
```

> ⚠️ **推送前确认这个仓库是空的**（没有 README、没有 .gitignore、没有 LICENSE）。
> 如果创建时勾选了 `Add a README file`，直接 push 会被拒绝（non-fast-forward）。
> 此时先执行 `git pull --rebase origin main` 再 push。
>
> 另外：想让项目公开可见（作品集通常需要），在
> `Settings → General → Danger Zone → Change visibility` 改为 Public。

### 步骤 2：初始化本地仓库

> 若 Git 版本较老不支持 `-b`，用 `git init && git branch -M main`。

**这一步是最后一道防线，不要跳过。**

```bash
git add .

```

确认输出中**不应出现**以下任何一项：

确认无误后核对文件清单：

```bash
git diff --cached --name-only | wc -l    # 文件数量
git diff --cached --name-only            # 完整清单
```

### 步骤 5：关联远程仓库并推送

```bash
git remote add origin https://github.com/jiangshaosi-design/rag.git

git push -u origin main
```

首次推送会弹出 GitHub 登录窗口（浏览器授权或输入 Personal Access Token）。

> **如果提示密码认证失败**：GitHub 早已不支持账号密码推送。请到
> `Settings → Developer settings → Personal access tokens → Tokens (classic)`
> 生成一个勾选 `repo` 权限的 token，在密码提示处粘贴 token 而非账号密码。
>
> 或改用 SSH（一次配置长期有效）：
> ```bash
> ssh-keygen -t ed25519 -C "你的邮箱"
> # 把 ~/.ssh/id_ed25519.pub 的内容粘贴到 GitHub → Settings → SSH and GPG keys
> git remote set-url origin git@github.com:<你的用户名>/<仓库名>.git
> ```

推送成功后访问 `https://github.com/<你的用户名>/<仓库名>` 即可看到项目。

## 三、发布后自查

### 必查项

- [ ] 打开仓库首页，确认 README 正常渲染
- [ ] 打开 `LICENSE`，确认署名是 `jiangshaosi-design`（如需改用真名，改完记得 commit + push）
- [ ] 确认仓库里**没有** `.env` 文件
- [ ] 打开 `.env.example`，确认里面的 key 都是 `sk-your-...` 占位符
- [ ] 确认仓库大小远小于 761 MB（正常应在 10 MB 以内）
- [ ] **确认两把旧密钥已在平台吊销**

### 建议项

- [ ] 添加 Topics 标签：`rag`、`langchain`、`faiss`、`streamlit`、`llm`、`agent`、`mysql`
- [ ] 在 README 里补几张界面截图（放在 `docs/screenshots/` 下引用）—— 截图是作品集项目最有效的说服力，注意截图里不要出现真实文档内容或密钥
- [ ] 添加 `.github/workflows/` CI（可选，需先补测试）
- [ ] 若仓库是 Public 且想接受贡献，可补 `CONTRIBUTING.md`

### 如果已经误提交了密钥

不要只是删文件再提交 —— 密钥仍留在 Git 历史里。必须重写历史：

```bash
# 方案 A：用 git-filter-repo（推荐，需先 pip install git-filter-repo）
git filter-repo --path .env.example --invert-paths

# 方案 B：最简单也最彻底 —— 删除 .git 重新初始化
rm -rf .git
git init -b main
# 重新走步骤 3 之后的流程
```

**但无论哪种方案，密钥都必须先去平台吊销。** 只要它被推送过哪怕一分钟，就要视为已泄露。
