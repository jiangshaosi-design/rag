# 系统流程梳理

> 本文档按**函数级调用链**梳理系统的四条主流程：文档入库、问答、删除、评估。
> 所有行号对应仓库当前版本，行号漂移时以函数名为准。

## 流程一：文档入库

**总入口**：`src/knowledge_base/pipeline.py:18 ingest_document(file_path, file_type, filename, on_progress)`

```
上传文件
  │
  ├─[0] 去重检查 ──────────── list_documents() 中已有同名 ready 文档 → 返回 error
  │
  ├─[1] 建记录 ────────────── add_document(Document(status="processing")) → doc_id
  │
  ├─[2] 解析 ──────────────── load_document(file_path, file_type, doc_id, on_progress)
  │        │                   ↓ 按扩展名分发到 LOADERS 注册表
  │        ├─ PDF  ─► PDFLoader.load()      loader.py:23
  │        ├─ DOCX ─► DOCXLoader.load()     loader.py:196
  │        └─ MD   ─► MarkdownLoader.load() loader.py:232
  │        │
  │        └─ 返回 (合并文本, 图片路径列表)
  │
  ├─[3] 图片上限校验 ──────── len(image_paths) > MAX_IMAGES_PER_DOC → 标记 error 返回
  │
  ├─[4] 分块 ──────────────── split_text(text) → chunks_text: list[str]
  │                           超 MAX_CHUNKS_PER_DOC → 标记 error 返回
  │
  ├─[5] 向量化 ────────────── 按 _BATCH_LIMIT(10) 分批调 _safe_call()
  │                           每批回调 on_progress，进度从 15% 推进到 75%
  │                           全部结果 np.vstack 成 (N, 1024) 矩阵
  │
  ├─[6] 写 MySQL ──────────── add_chunks_batch(chunk_records)   一次性 executemany
  │                           ↓ 再回写 faiss_id
  │                           SELECT id FROM chunks WHERE document_id=%s ORDER BY chunk_index
  │                           UPDATE chunks SET faiss_id = str(id) WHERE id = %s
  │
  ├─[7] 写 FAISS ──────────── load_index() → 无则 create_index()
  │                           normalize(vectors)              L2 归一化
  │                           add_to_index(index, vectors, chunk_ids)
  │                           save_index(index)
  │
  └─[8] 完成 ──────────────── update_document_status(doc_id, "ready", len(chunks_text))
                              返回 {"doc_id", "chunk_count", "status": "ready"}
```

**异常处理**：整段包在 `try/except`（`pipeline.py:125`），任何异常都会把文档标记为 `error` 并返回 `{"status": "error", "error": str(e)}`，保证不会在库里留下 `processing` 悬挂状态。

### 1.2 分块子流程（`splitter.split_text`）

```
原文（含 [TABLE_START]...[TABLE_END] 表格块）
   │
   ├─ ① _protect_blocks()
   │      正则 \[TABLE_START\].*?\[TABLE_END\] (DOTALL)
   │      → 表格块替换为 __TABLE_BLOCK_N__
   │      → 记录 {占位符: 原文}
   │
   ├─ ② RecursiveCharacterTextSplitter(
   │        chunk_size=1000, chunk_overlap=100,
   │        separators=["\n\n", "\n", "。", "！", "？", "；", ".", "!", "?", ";", " ", ""])
   │      → coarse_chunks
   │
   ├─ ③ 逐块判断：
   │      len(coarse) <= 500  → 直接保留
   │      len(coarse) >  500  → _apply_sliding_window(coarse, 500, 250)
   │                             窗口 500、步长 250（50% 重叠）
   │
   └─ ④ _restore_blocks()
          占位符还原为原始表格文本
```

**关键约束**：滑动窗口只在**单个递归块内部**滑动，不跨段落/章节边界。

### 1.3 存储映射

| 存储 | 内容 | 键 |
|------|------|-----|
| MySQL `documents` | 文件名、类型、路径、大小、块数、状态 | `id`（自增） |
| MySQL `chunks` | 文本块内容、块序号、token 数 | `id`（自增），`faiss_id = str(id)` |
| FAISS `IndexIDMap` | 归一化向量 (1024维) | 整数 ID = `chunks.id` |

```
chunks.id  ──►  faiss_id (字符串，存 MySQL)
           ──►  FAISS 向量 ID (整数)
```

> 检索时：FAISS 返回 `(id, score)` → 用 `str(id)` 去 `chunks.faiss_id` 反查全文。这是双存储之间的唯一连接点。

### 2.1 缓存查询子流程（`tools.check_history`）

```
question
   │
   ▼
repository.search_similar_question(question, top_n=3)
   │
   ├─ 阶段一：SQL 粗筛
   │    关键词 = question 按空格切词，len >= 2
   │    无关键词 → 直接返回 []
   │    SELECT ... FROM chat_history
   │    WHERE role='user' AND (content LIKE %kw1% OR content LIKE %kw2% ...)
   │    ORDER BY created_at DESC LIMIT top_n*3
   │
   ├─ 阶段二：Embedding 精排
   │    对每条候选：cosine_sim(embed(question), embed(候选))
   │    仅保留 sim > 0.85
   │    按相似度降序，取 top_n
   │
   ▼
命中 → get_answer_for_question(best["question"])
        按 session_id 找该提问之后的第一条 assistant 消息
   │
   ▼
返回带相似度、原问题、缓存答案、时间的格式化文本
```

> 未命中时返回 `"未命中历史缓存，需要正常检索。"`，Agent 据此转而调用 `search_knowledge_base`。

### 2.2 知识库检索子流程（`tools.search_knowledge_base`）

```
query
   │
   ├─ load_index() → 索引为空 → "知识库为空，请先上传文档。"
   │
   ├─ embed_text(query) → query_vec (1024维)
   │
   ├─ search(index, query_vec)
   │     normalize(query)
   │     index.search(query, min(TOP_K, ntotal))
   │     过滤 faiss_id >= 0
   │     → [(faiss_id, score), ...]
   │
   ├─ get_chunks_by_faiss_ids([str(id) for ...])
   │     ORDER BY field(faiss_id, ...)  ← 保持 FAISS 的相关度排序
   │
   └─ 逐块格式化：
        [来源: {doc.filename} | 块{chunk.chunk_index}] (相关度: {score:.2f})
        {chunk.content}
      段间以 "\n\n---\n\n" 分隔
```

### 2.3 来源提取（`agent.py:136` 起）

```python
for block in tool_content.split("\n---\n"):
    m = re.search(
        r'\[来源:\s*(.+?)\s*\|\s*块(\d+)\]\s*\(相关度:\s*([\d.]+)\)',
        block)
    if m:
        sources.append({
            "filename":    m.group(1).strip(),
            "chunk_index": int(m.group(2)),
            "score":       float(m.group(3)),
            "content":     block.split("\n", 1)[1].strip()[:300],
        })
```

> ⚠️ 这个正则与 `tools.search_knowledge_base` 的输出格式是**隐式契约**。改动任一侧必须同步改动另一侧。

## 流程三：文档删除

**入口**：`src/knowledge_base/pipeline.py:131 remove_document(doc_id)`

```
get_chunks_by_document(doc_id) → 取出该文档所有 chunk 的 id
   │
   ├─ ① MySQL  ─ delete_document(doc_id)
   │             外键 ON DELETE CASCADE 自动清理 chunks
   │
   ├─ ② FAISS  ─ remove_from_index(index, chunk_ids)
   │             index.remove_ids(np.array(ids, dtype=int64))
   │             save_index(index)
   │
   ├─ ③ 图片   ─ glob 匹配 doc{doc_id}_*.{png,jpg,jpeg,gif} 逐个 os.remove
   │             单文件删除失败（OSError）静默跳过
   │
   └─ ④ MinerU ─ shutil.rmtree(data/mineru_output/doc_{doc_id}, ignore_errors=True)
```

> 四路清理保证不留孤儿数据。若只删 MySQL，FAISS 中会残留向量且检索时无法反查全文。

## 流程四：评估

### 4.1 手工用例模式

**入口**：`python -m src.evaluation.run_eval` → `evaluate_rag(TEST_CASES, k=5)`

```
for each test_case:
   ├─ precision_at_k(question, expected_keywords, k)
   │     检索 Top-K → 逐块检查是否命中任一关键词 → hits / total
   │
   ├─ recall_crude(question, expected_keywords, k)
   │     检索 Top-K 拼成全文 → 命中关键词数 / 期望关键词总数
   │
   ├─ invoke_agent(question) → answer, sources
   │
   ├─ faithfulness(answer, sources)      [可选，消耗 LLM]
   │     来源 + 回答一起喂给 DeepSeek
   │     要求输出 "分数: X.XX" 与 "判定: ..."
   │     正则解析；异常时兜底 0.5 分
   │
   └─ answer_relevance(question, answer)
         余弦相似度 → min(cos / 0.8, 1.0) 归一化
   │
   ▼
summary = {avg_precision, avg_recall, avg_faithfulness, avg_relevance}
```

### 4.2 自动出题模式

**入口**：`metrics.py:298 evaluate_rag_auto(num_cases)`

```
generate_test_cases(num_cases)
   │
   ├─ list_documents() → 仅取 status='ready'
   │
   ├─ 随机抽文档 → 抽块（优先 100 < len < 2000 的中等长度块）
   │
   ├─ LLM 反向出题：
   │     prompt = "根据以下文本片段，生成一个可以用这段文字回答的问题..."
   │     只保留 5 < len(question) < 200 的结果
   │
   ▼
从源内容提取关键词作为 benchmark
   re.findall(r'[一-龥a-zA-Z0-9]+', source_content)
   过滤 3 <= len <= 8，去重取前 8 个
   │
   ▼
复用 evaluate_rag() 走同一套四指标
```

> **为什么要自动出题**：手工用例容易被"只测自己会答的题"的偏差污染。自动出题从知识库随机采样、LLM 反向生成问题，再检查检索能否召回**原始源块**，是对检索质量的更客观的度量。

## 附：关键设计决策与原因

| 决策 | 原因 |
|------|------|
| FAISS ID 用 `chunks.id` 而非 `{doc}_{idx}` 复合串 | IDMap 需要 `int64`；自增主键天然唯一且可直接反查，避免解析字符串 |
| `IndexIDMap(IndexFlatIP)` + L2 归一化 | FAISS 没有原生余弦索引，归一化后内积等价余弦；IDMap 支持 `remove_ids` 才能实现删除 |
| 中文路径降级到临时目录 | FAISS C++ 层用 `std::string` 处理路径，非 ASCII 会失败 |
| 表格用 `[TABLE_START]` 占位符保护 | 表格是强语义单元，被切断后单元格数据失去列名上下文 |
| 滑动窗口限定在递归块内部 | 跨块滑动会把不相关章节拼接，污染语义 |
| 图片先复制再校验上限后描述 | Qwen-VL 调用按量计费，必须避免为超限文档白花钱 |
| 图片描述用 3 线程 | 实测大文档（800 张图）从 67 分钟降至 22 分钟 |
| 上传走后台线程 + 轮询 | MinerU 解析 286 页 PDF 可能超过 20 分钟，同步 HTTP 会超时 |
| `agent.py` 打印诊断日志 | ReAct 循环异常（如无限重试）难以从返回值定位，需看到消息级细节 |
| LLM 自动出题评估 | 消除人工用例选择偏差 |
